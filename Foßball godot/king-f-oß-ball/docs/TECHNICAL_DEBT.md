# Technical debt

1. `match_manager.gd` was split: save/restore moved to `MatchSnapshot`, rules to `MatchRules` / `MatchRestarts`. It is again ~720 lines (replay, crowd and environment wiring were added) (placement, pause, HUD, possession, results); next extraction candidates: pause/results flow.
2. `AppHub` and `GameManager` are large singletons; new systems should take dependencies as arguments.
3. `scripts/player` vs `scripts/players` naming is confusing (controller vs data/visual).
4. No static scan for broken scene/resource references.
5. README still has an old paragraph saying Phase 5+ is "not started".
6. Matches simulated without the engine have no real statistics; season awards use a documented statistical model for them (`SeasonStats`).
7. Performance was measured only on a software renderer.
8. Controller input navigation is not tested.
9. The full suite takes about 13 minutes (the 12-season test is the bottleneck, ~15 s of league simulation per season).
10. The transfer history stores only the week, so old transfers appear in the current season in the news.
11. Crowd audio and the rain / floodlight visuals are verified by state only (no listening, no screenshot of the effects).
12. The negotiation API has no screen; the financial report has no screen.
13. A career save in the real data pack is about 8 MB of JSON (measured after one season); season statistics are part of it until the season ends.
14. AI attack (partly fixed in the review): before, 18 full AI-vs-AI matches (2 minutes, three difficulties) gave 0-3 shots, 0-34 passes and 2 goals in total, with the tackle system on or off. Causes found by tracing the ball: the two strikers duelled at the centre circle for the whole match (no forward pass target at kick-off, no way round a blocker). Fixes: early pass when blocked, sideways / back pass when pressed with nothing ahead, a run that bends round the blocker, shooting from 1.3 x the shoot range with an open lane, the team pushing up with the ball (forwards run ahead through `support_offset`). Measured with `tools/sim_matches.tscn` (3 matches x 2 min, normal / hard): passes 42 / 19 -> 132 / 100, shots 3 / 1 -> 5 / 7, goals 0 / 0 -> 1 / 1, 0 red cards, no stalemate (closest carrier to goal <= 29 m in every match). Second round: tracing the AI's shoot presses showed that only about one in five became a real shot (the press was sent when the ball was not within reach, or the player ran on and the charge was cancelled). `_can_start_kick` now checks the ball is in reach and the player stands still while a kick charges: conversion of attempts to shots rose to about 40 %, passes 127-223 per 3 matches, goals 1. Third round: crosses (a wide carrier in the final third lobs to a free team-mate in the box), through balls (forward passes lead the receiver by up to 4 m into free space), pass / lob power charged for the distance, shots as a quick tap aimed 2 m inside the post away from the keeper, and the aim corrected for the kick systems' bend towards the ball (`PlayerAI.compensated_aim`); before, many shots left the foot 20-90 degrees off target. Also a statistics bug: a goalkeeper reaching a shot was counted as a block, so saves and shots on target were missing; now it is a save. Measured (3 x 2 min each, normal / hard / normal with other seeds): shots 11 / 17 / 17, on target 3 / 3 / 5, goals 0 / 0 / 1. Still: goals are rare (the keepers save most shots on target) and passes vary a lot between matches (42-131); before this round: 0-4 shots per match (target 5-12) and one hard match with 0 shots; more work: crosses, through balls, finishing quality, a goalkeeper that does not always clear to the middle. The sample is small (6 matches per setting).
15. The first foul system (before the tuning in the review) gave 3 red cards per hard match; the tackle rate, foul share and card severity were reduced (see `MatchRules`); re-check with `tools/sim_matches.tscn` after any AI change.
16. World load (QA review 2026-11): loading the `real_2025` pack read ~324 JSON files one after another and took 11.8 s, over the 10 s budget in `db_performance_validation`. The files are now READ CONCURRENTLY (`TeamDatabase._read_files_concurrently`, `WorkerThreadPool`); parsing and object creation stay on the main thread. Measured: load_world 11831 ms -> 5439 ms, reload 9087 ms -> 3509 ms, first kit texture 2045 ms -> 1433 ms (budget 1500 ms). `tools/profile_load.tscn` prints the cost centres (read / JSON parse / from_dict / validate / appearance generation / kit repair). Still open: ~0.8 s of the load is generating the appearance of all 8013 players, and the search over all players is ~0.5-1.8 s — both are candidates for a lazy or indexed approach.
17. "ObjectDB instances were leaked at exit" in the validation suites was NOT a game defect: the suites build their own `TeamDatabase` with `.new()` and never add it to the tree, so every copy kept its whole world alive (12127 instances in `db_players_validation`, up to 91712 in `db_crests_validation`). The autoload now releases those orphan instances in `TeamDatabase._exit_tree` (4 instances left). Do not "fix" this again in the game code — create the database through the autoload, or free it in the test.
18. The developer tools `sim_matches` and `match_ui_shot` hard-coded two clubs of the DEFAULT world (`club_royal_harbor`, `club_northgate_utd`) that do not exist in the shipped packs, so `MatchSetup.validate()` failed, `MatchManager.begin()` returned an error string the tools ignored and the tool then waited forever on a null match state. They now pick the pair from the loaded database (`tools/dev_team_picker.gd`) and quit with a message instead of hanging.
19. WORKFLOW TRAP: a NEW script with a `class_name` is only usable after the project re-imported its global class list. Running a headless suite before that gives "Parse Error: Could not find type X in the current scope" in EVERY suite that touches the new class (and those suites then abort with 0 passed / 0 failed, which looks like a broken game). Fix: `godot --headless --path . --import` (or open the editor once) after adding a `class_name` script, then run the tests. Seen with `InputSettings`, `HumanAimAssist` and `TouchControls` (2026-11).
